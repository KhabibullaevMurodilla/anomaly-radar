What "flagged" means here

1
Parse — real wire format for both protocols: Modbus/TCP's MBAP header + function-specific PDU, and Siemens S7comm's TPKT/COTP/S7 framing, request↔response matched by TCP connection order (not a transaction/reference ID — real devices often never increment it).
2
Group into sessions — one row per (protocol, client, server, unit) conversation: request rate, exception rate, how many distinct function codes it used, how many of those aren't standard for that protocol.
3
Compare to peers — each session is scored against the OTHER sessions talking to the same device over the same protocol, not against a fixed threshold. A session flagged here is a statistical outlier among its own peer group.
This in-browser tool runs the population-relative session detector — the one built after testing against this exact real capture showed a per-transaction model structurally misses an attacker who's anomalous from their first packet. The full project (parser, both detectors, test suite) is on GitHub.
